# Traceability: requirement IDs to features, acceptance checks and tests

Source: `specs/product/handoff-v1.2.md` (Business rules, Payments, LINE, Roles, Text and language) and `specs/product/prd-v1.2.md`. Written 30 Oct 2026.

**How to read this.**

- *Feature* is the backlog number from the hand-off (F01 to F16). The first feature listed owns the rule; the others touch it.
- *Acceptance check* is copied from the hand-off. If the hand-off column is empty, the row says **GAP** and the *Proposed check* is QA's reading of the requirement text, with no new rule added. A proposed check needs approval from a person (gate 1, requirements.md) before it counts.
- *Level*: **U** unit, **I** integration (real Postgres, fakes at the edge), **C** concurrency, **R** row level security, **E** end to end (Playwright), **S** static check or lint, **M** manual on device. Test names such as E2E-05 refer to `test-strategy.md` section 3.4.
- *Q-nn* refers to `open-questions.md`.
- *Status* is Red (no test yet) for every row today, because no code or approved requirements exist. It changes as tests land.

**Counts are generated.** `acceptance-coverage.md` (generated by `tests/acceptance/generate.ts` from the hand-off and the approved `requirements.md` files) lists all **76** hand-off IDs, whether the hand-off gives a check, and how many approved criteria cover each. Today **521** approved criteria (F01 to F06, F10, F11, F12) each have a `test.todo` in `tests/acceptance/`, and `coverage.spec.ts` fails when a criterion has none (D126).

**Still without any check or approved criterion (11):** TEXT-03 to TEXT-06 (cross cutting, no feature owns them), CANCEL-03 and CANCEL-04 (F09), CLASS-01 and CLASS-02 (F08), PROMO-02 (F14), RCPT-01 and RCPT-03 (F13). F07, F08, F09, F13 and F14 have no approved requirements yet, so COACH-01 to COACH-04, CANCEL-01, CLASS and RCPT rows below still rest on the hand-off check and QA's proposals. **PAY-08** is deferred (F16).

Rows below were written on 30 Oct before F03 to F12 were approved. Where a row says **Approved criteria**, the criteria are in the named feature's `requirements.md` and in the skeletons. Where it still says **GAP**, nothing approved exists yet. Check present but thin (7): AUTH-02, BOOK-05, PKG-02, CANCEL-01, PAY-01, PAY-02, RCPT-02 were thin in the hand-off; the approved criteria for AUTH-02, BOOK-05, PKG-02, PAY-01 and PAY-02 now cover them. IDs added to the hand-off since: BOOK-06, WAIT-01, ADMIN-01 to ADMIN-17, CPORT-01 to CPORT-07, ROLE-01, ROLE-02, PLAT-07, LINE-07; they are in the generated inventory and in the per feature skeletons.
